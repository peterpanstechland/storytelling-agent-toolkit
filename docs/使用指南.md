# 使用指南

面向「彼得潘的科技谷」的日常成片：活动/商单、Maker 项目宣传、个人 Vlog。命令都来自当前仓库的脚本和 `SKILL.md`，示例默认在**仓库根目录**执行。

装进 Agent 之后，storytelling 的命令改到 skill 目录里跑（该目录就是含 `SKILL.md` 的文件夹）。例如 `python publishing/wechat.py`、`python video/run autocut`。pxl 用 `node bin/pxl.js`。两条 skill 互不调用，只用对方已经能读的文件（PNG、GIF、JSON、MP4）。

详细契约仍以这些文档为准：[SKILL.md](../skills/storytelling/SKILL.md)、[自动剪辑](../skills/storytelling/references/auto-edit.md)、[代码成片](../skills/storytelling/references/code-video.md)、[pxl](../skills/pxl/SKILL.md)、[发布](../skills/storytelling/references/publishing.md)。

## 1. 各块做什么、什么时候用

| 块 | 位置 | 用来做 | 什么时候用 |
|---|---|---|---|
| 叙事核心 | `skills/storytelling` | 从素材写成面向新读者的故事：问题、证据、转折；`brief.json` 与各平台本地发布包 | 任何一条片子或一篇文章开工时。它不代写口播，也不上传 |
| 图文卡片 | `scripts/render_cards.py` | 五种版式的 PNG：`cover`、`photo-overlay`、`stat`、`quote`、`process`，并检查字体、换行、溢出 | 小红书轮播、公众号配图、封面。数字要自带含义、范围和单位 |
| 公众号发布 | `publishing/wechat.py` | 本地预览、上传正文图/封面、草稿、提交发布、查状态 | 长文定稿、并且账号 API 已授权之后。其他平台只做编辑器交接，见 [platforms.json](../skills/storytelling/publishing/platforms.json) |
| 少量成片剪辑 | `video/run render` / `narrate` / `mix` | 已经定好的切点：精确裁切、中英字幕、旁白装配、混音 | 几段素材、切点已定。不要用它做运镜、转场或 360 |
| autocut（vcut） | `video/run autocut` | 多设备项目：拍摄清单、设备识别、缺镜头、风格化粗剪、360 运镜、MP4 预览、剪映草稿 | 活动/商单/Maker/Vlog，素材来自多台相机。粗剪仍要人看故事、身份和事实 |
| pxl 像素画 | `skills/pxl` | `.px.js` → PNG、精灵表、GIF | 图卡插画、文章配图、片头或短插入。不剪实拍 |
| 代码成片 | `skills/storytelling/codevideo` | 51 个 Lemo 风格说明、15 个动态图形提示词、卡拉 OK 词级时间轴、节拍角色页、标题卡颗粒/光晕/暗角/粒子 | 画面是代码画出来的，或要给实拍加标题卡/歌词擦除。实拍粗剪仍走 autocut |

分工口诀：故事和口径用 storytelling；多机位粗剪用 autocut；几刀定稿用 `render`；像素和代码画面是素材，再送进图卡、网页渲染或剪辑计划。

## 2. 安装与依赖

### 装进 Agent

安装器只复制选中的 skill，不改全局模型或其他 skill。目标里已有同名目录会直接停。

```bash
python3 scripts/install_skill.py --target ~/.codex/skills
python3 scripts/install_skill.py --skill pxl --target ~/.codex/skills
python3 scripts/install_skill.py --skill all --target ~/.codex/skills
```

`--skill` 可选 `storytelling`（默认）、`pxl`、`all`。`--target` 必填，下面会各建一个子目录。其他 Agent 用它自己的 skills 目录，或直接读对应的 `SKILL.md`。

### 依赖

| 依赖 | 谁需要 | 怎么装 |
|---|---|---|
| Python 3.10+ | 叙事、图卡、视频、公众号、autocut | 系统 Python。建议仓库内 `.venv` |
| Pillow | 图卡；`inspect` 拼图；autocut 的 HUD 文字 | `python -m pip install Pillow`。图卡还要系统里的中文字体，用 `--font` 指定。Linux 常用 Noto Sans CJK，仓库不带字体 |
| FFmpeg / FFprobe（在 `PATH`） | 剪辑、混音、网页导出 MP4/GIF、autocut | 自行安装。`doctor` 会检查 libx264、libass |
| Node ≥ 18 | 网页逐帧渲染 `capture_web.mjs` | 仓库根目录 `npm install`，然后 `npx playwright install chromium` |
| Node ≥ 22.18 | pxl | `node skills/pxl/bin/pxl.js` 无运行时依赖。类型检查和测试：`cd skills/pxl && npm ci && npm run check` |
| autocut 基础包 | 只有 `autocut` 子命令 | `python -m pip install -r skills/storytelling/video/requirements-autocut.txt`（typer、rich、PyYAML、pydantic、httpx、NumPy、OpenCV） |
| autocut 可选包 | 剪映、PySceneDetect、节拍、YOLO、HUD 文字 | `python -m pip install -r skills/storytelling/video/requirements-autocut-optional.txt`。缺了只降级，不挡 `new → shotlist → ingest → analyze → plan → render` |
| faster-whisper | `run transcribe`，以及 autocut 口播识别 | `python -m pip install -r skills/storytelling/video/requirements-asr.txt`。权重不在仓库里 |

检查：

```bash
python skills/storytelling/video/run doctor
python skills/storytelling/video/run doctor --require autocut
python skills/storytelling/video/run autocut doctor
```

### GPU Whisper

autocut 默认 `asr.engine: builtin`。`asr.device: auto` 时，本机有 CUDA 就用 `large-v3-turbo`、`float16`；否则降到 `cpu_model`（`small`）和 `int8`。CUDA 加载失败时会改走 CPU。Windows 上若提示缺库，按程序原文安装 `nvidia-cublas-cu12` 与 `nvidia-cudnn-cu12`。多卡用 `asr.device_index`。环境变量 `VCUT_ASR_DEVICE`、`VCUT_ASR_MODEL` 优先于配置。

首次会从 Hugging Face 拉模型。国内可在 `settings.local.yaml` 写 `asr.hf_endpoint: https://hf-mirror.com`，或设 `HF_ENDPOINT`。也可以把 `asr.model` 指到本地目录。`run transcribe` 默认不下载，只有加上 `--download` 才允许拉模型；它不上传音频。

已有转写就不要让 autocut 再转一次：`autocut import-transcript`，或把 `asr.engine` 设为 `toolkit`（调用同一支 `transcribe.py`）。

### 剪映草稿（Windows）

`autocut draft` 需要已安装的 pyJianYingDraft。Windows 上草稿目录默认识别为 `%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft`。改位置用 `settings.local.yaml` 的 `jianying.drafts_dir`，或环境变量 `VCUT_JIANYING_DRAFTS`。

生成的是明文 JSON。上游说明可在剪映 5.9 和 10.8 打开。界面自动化导出只适用于剪映 ≤ 6，本仓库不用那条路。非 Windows 会先写到项目里的 `drafts/jianying/`，素材路径是当前机器的；换到 Windows 后要在那台机器上重新跑 `autocut draft`。草稿是近似，预览 MP4 才是对照。用过的剪映素材和 VIP 标记写在草稿目录的 `vcut_说明.txt`。剪映软件、素材库和会员内容不随本仓库提供。

个人配置写 `skills/storytelling/video/autocut/config/settings.local.yaml`（只写要改的键），或设 `VCUT_CONFIG_DIR`。密钥只走环境变量：`DASHSCOPE_API_KEY`、`GEMINI_API_KEY`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET`。

## 3. 三条片子怎么串

四台相机在 `devices.yaml` 里的身份：

| 相机 | id | 类型 | 拍什么 |
|---|---|---|---|
| Insta360 X5 | `x5` | 360 | 进场、人群、隐形自拍杆、第三人称走。正式片用 Insta360 Studio 导出 **2:1 全景 MP4**（开防抖和水平校正）再 `ingest`。`.insv` 只走 `x5-stitch`，且先 `--preview-only` |
| Insta360 Ace Pro 2 | `ace_pro_2` | 运动相机 | 运动、夜景、舞台、慢动作。`PRO_LRV_` 是低码率代理，不要导入 |
| Insta360 GO Ultra | `go_ultra` | 口袋相机 | 胸前/帽檐第一视角、焊接装配、狭小空间 |
| 一加 12 | `android_phone` | 手机 | 口播、铭牌、产品、微距、拍屏幕。识别关键字已包含 `OnePlus 12`、`PJD110`、`CPH2581`。认错了跑 `autocut probe 文件`，把真实关键字补进本机的 `devices.yaml`（不要提交序列号） |

竖屏（商单默认 9:16）用 `reframe.vertical: smart`：主体进得了竖屏窗口就跟随，否则整幅加模糊背景。

项目默认建在 `~/Videos/vcut-projects`（`projects_root` 为空时）。用 `autocut new … --dir` 或 `VCUT_PROJECTS_ROOT` 改地方。`ingest` 的 `--mode ref`（只登记路径）或 `link`（同盘硬链接）适合大文件；默认 `copy` 会复制。

### 共用骨架

1. **故事**：`story.py init` 建 `brief.json`，按 [故事设计](../skills/storytelling/references/story-design.md) 写给第一次看的人。`validate` 查结构和引用，不证明事实为真。
2. **开拍前**：`autocut new`，把主题、口播、功能点或商单 brief 写进 `project.yaml`，再 `shotlist`。清单按类型、主题和**当前可用设备**出镜头、最短时长和提示。
3. **拍完**：按上表导出/筛选，`ingest` → `analyze` → `gaps`。缺必拍就补。`plan` 得到 `edl.json`。手改过的方案不要再跑 `plan`（会覆盖；旧稿在 `analysis/edl_history/`），只重跑 `render` / `draft`。
4. **粗剪**：`render --quick` 看半分辨率，再去掉 `--quick`。要剪映就 `draft`。一条龙是 `autocut run`（analyze → gaps → plan → render → draft）。
5. **标题与歌词**：风格自带标题字。像素片头用 pxl 导出**有时长的 GIF**，放进 `edit.json` 当一个 clip（`in`/`out` 落在该时长内）。静止 PNG 不能当 clip；要定格就做成短 GIF，或放进本地网页用 `capture_web.mjs --mode video` 导出。标题卡质感用 `looks.py`（颗粒宜轻；要忠实记录现场的镜头不要用它调色）。卡拉 OK 用 `karaoke.py` 写 `lyrics.ass`，词级时间自己提供；再在视频流程里用带 libass 的 FFmpeg 烧录，并对照人声看擦除。口播字幕用 autocut 自己的 SRT（`render --subs burn|sidecar|both`，默认烧录）。
6. **图文**：同一条故事的关键画面做成卡片。pxl 的 PNG 放进卡片 JSON 所在目录，当 `photo-overlay` 的 `image`。
7. **公众号**：`story.py pack --platforms wechat-article` 只出本地包。文章 JSON 按 [发布指南](../skills/storytelling/references/publishing.md) 填好后：`preview` → `upload-body` / `upload-cover --execute` → 把返回的 URL 和封面 `media_id` 写回正文 → `draft --execute` → 你明确授权这篇草稿公开之后才 `publish --execute --authorized` → `status --execute`。草稿、已提交、已公开不是同一状态。

`export-edit` 会丢掉转场、运镜、特效、变速和音效，列出会丢的项。要完整成片用 `autocut render`。旁白可用本地 `clone`（IndexTTS-2.5）、外部 TTS 或录音，`narrate` 只装配，再用 `import-narration` 放进 EDL（配乐闪避会打开）。

### 活动 / 商单

| | 活动 `event` | 商单 `sponsored` |
|---|---|---|
| 默认 | 120 秒、16:9、风格 `energetic`，平台 B站 / 小红书 | 60 秒、9:16、风格 `energetic`，平台 抖音 / 小红书 |
| 结构 | 到场 → 口播开场 → 氛围与内容 → 人 → 收束 | 钩子 → 我是谁 → 品牌 → 必拍体验 → 卖点口播 → CTA 和 Logo |
| 开工必填 | `project.yaml` 的 `event.name` / `date` / `location`、`theme`、`cta` | 同上，外加 `sponsor:`：`must_show`、`key_messages`、`forbidden`、`logo`、`logo_position`、`cta`。缺必拍会被 `gaps` 标出 |

```bash
python skills/storytelling/video/run autocut new "展会当天" --type event --duration 120
python skills/storytelling/video/run autocut new "品牌体验" --type sponsored --duration 60 --aspect 9:16 --platform 抖音 --platform 小红书
python skills/storytelling/video/run autocut shotlist "展会当天"
```

机位：X5 拍场馆外景和走进去的一条、人群；Ace Pro 2 拍舞台和运动；GO Ultra 挂胸前拍上手体验；一加 12 拍主视觉、铭牌、产品英雄镜头和口播（品牌名读准，一句一条，方便剪）。

风格可换：燃剪用 `beat_max`；回顾用 `cinematic` 或 `premium_film`；几乎全是 X5 用 `cinematic_360`；科技类商单用 `cyber_glitch` 或 `premium_maker`。名字以 `autocut styles` 为准。第一人称口播时画面给作者或项目，不要压在别人的特写上。

### Maker 项目宣传

默认 90 秒、16:9、`tech_minimal`，平台 B站 / YouTube。结构是痛点 → 项目 → 制作 → 功能（`maker.features` 的每一条会变成一个镜头和一条字幕标题）→ 收束。

```bash
python skills/storytelling/video/run autocut new "ESP32 灯" --type maker --duration 90 --style premium_maker
```

然后在 `project.yaml` 填写 `maker.project_name`、`maker.features`、`voiceover.script`。GO Ultra 拍焊接和装配；一加 12 拍口播、PCB 微距和屏幕；X5 拍工作台和真实场景里的第三人称；Ace Pro 2 拍成品最亮的那一下。科技向还可以用 `cyber_glitch` 或 `tracker_hud`（终端 HUD 卡）。功能演示一段一个功能，头尾各留约 2 秒。

成片之后：`process` 卡片写步骤，`photo-overlay` 标元件；长文走公众号。代码界面若要做成讲解动画，用代码成片的风格说明加 `capture_web.mjs`，不要把实拍硬套成像素。

### 个人 Vlog

默认 180 秒、16:9、`warm_daily`，`voiceover` 关闭，保留随拍时的自然说话。平台 B站 / 小红书。结构是开场 → 按时间经过 → 有意思的瞬间 → 结尾。

```bash
python skills/storytelling/video/run autocut new "周末出门" --type vlog --duration 180
```

X5 举高做第三人称走；Ace Pro 2 拍骑行和交通工具；GO Ultra 拍吃东西、买东西、动手；一加 12 拍食物和光影特写。每个地点先留约 5 秒空镜。旅行回忆可改 `film_retro` 或 `premium_film`；走路很多再用 `cinematic_360`。

Vlog 通常不需要卡拉 OK。只有某段确实有词、并且你能给出每个词的起止时间，才跑 `karaoke.py`。

## 4. 命令速查

路径换成你的项目目录。`/tmp` 示例不读你的素材、不连账号。


`transcribe` 默认 `--device cpu`、`--compute-type int8`。计划示例在 [video/examples](../skills/storytelling/video/examples)，里面的路径要换成你的文件。字幕时间用的是**源素材时钟**。

`styles.py find` 同时搜 Lemo 风格和动态图形提示词。读到的 `STYLE.md` 是给上游渲染器写的说明，在这里要改写成带 `window.renderFrame` 的本地页，再交给 `capture_web.mjs`。`examples/lyrics.json` 是工具自带的虚构例句，不是可以当别人的歌发布的歌词。`catalog.py` 只存索引和链接，提示词正文在上游。

## 用自己的声音配音，以及只调色的修订

`video/run clone` 已接入本地 IndexTTS-2.5：先检查参考录音与权重，生成一小段试听，再分段设置好奇、清晰、投入、温暖等表达及语速。失败后可续跑；台词、参考声音或模型变化会使对应缓存失效。随后用 `transcribe` → `voice-check` 校对，再用 `narrate` → `mix` 装配。完整命令、私有计划和环境配置见 [声音克隆指南](../skills/storytelling/references/voice-cloning.md)。已有授权直接记录，不需要重复问一遍；录音与模型不要放进公开仓库。

已经认可的成片只需提亮时，使用 `video/run grade`，指定时间段和实拍画面区域，保留包装颜色、原声、字幕文件和镜头时序。它是 SDR 曲线调整，不是假定相机 Log 类型的 LUT 转换。需要将某平台版的比赛画面换成虚拟画面时，还要检查录屏、片头、缩略图和转场里的嵌套素材。详见 [成片修订指南](../skills/storytelling/references/video-revisions.md)。
