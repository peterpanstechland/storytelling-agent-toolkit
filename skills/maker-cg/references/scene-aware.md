# 从实拍推导 CG

Agent 的视觉观察负责语义和创意；本地深度模型只估计可见形状，不识别产品功能。先查看起始、动作和结尾的实际帧，记录到本片计划的 `scene_analysis`，再生成场景。文件名与随机预设不能代替这一步。

## 可执行的观察

- `source_keyframes` 指向实际查看过的文件。
- `observed_objects` 描述轮廓、开口、连接处和应保留的真实活动部分。
- `materials` 记录采样位置、颜色、粗糙度判断和可用纹理来源。
- `lighting` 记录主要光源、明暗分界、环境反射和阴影方向；没有看到的光源标为估计。
- `effect_design` 说明哪一部分怎样改变，原位置露出什么，以及怎样回到实拍。
- `geometry_status` 区分实际模型、实拍可见表面、相对深度与想象的补全。

这些字段是推理记录，不能仅通过填满字段证明理解正确。实际渲染必须表现出记录中的结构与交互。

## 根据结构选择几何

本机的多视图路径见 [场景工程](scene-package.md)：`camera.mode=reconstructed` 使用 DA3。下述 `reconstruction.depth_model` 是保留的单视图 DA2 相对深度路径，不能将其当作多视图相机解算。

已有 CAD/扫描模型时先检查版本和外形再配准。立面、门板、外壳等可见区域可以用 `source_surface` 建立带原片纹理和厚度的网格，沿实际接缝分片。曲面或多深度区域可以启用本地深度估计；需要绕到不可见一面时，增加真实模型或多视图重建。不要从单帧相对深度推断隐藏内部。

`reconstruction.depth_model` 指向已下载的 Depth Anything V2 Small HF 目录。prepare 会在本地推理，生成 `perception.npz`、`depth-overview.jpg` 和有来源的 `perception.json`。目录需包含 model.safetensors、config.json、preprocessor_config.json，建议保存模型版本与许可的 source.json。推理不上传素材、不自动下载。需要 Python torch 与 transformers。

相对深度沿原相机射线回投到跟踪平面，`relief_strength` 控制起伏量；默认 0.12。它没有真实距离标定，不能作为测量值。原本平整的表面应压低起伏，不让深度噪声改变制造结构。

## 虚实交界

让变化从原物体轮廓、接缝或接触点发生。保留原材质的纹理尺度和颜色，再补转动后显露的厚度与背面。源画面已经包含受光，照片材质适合小角度动作；大角度翻转需要可重照明的材质和现场光照估计。

物体移开后，应能解释背后的画面：真实内部照片、背景修补或合理的三维内部。图片参考需匹配投影、比例和连续性，不能将同一局部重复粘到不同碎片后面。屏幕、人、植物等动态原片区域用几何避让或前景遮罩保护。需要投影、反射或双向遮挡时，在场景中建立对应代理与通道并检查实际效果。

先看一张最容易穿帮的静帧，再看起效、快速运动、停留和复位。核对边缘滑动、旧物体残留、纹理复制、物体穿插及光照变化。数值跟踪准确不能替代这些检查。
