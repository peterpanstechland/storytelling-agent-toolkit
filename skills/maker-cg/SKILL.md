# Maker CG

从用户想看到的动作出发，完成实际可预览的视频。使用本地 OpenCV、Blender 和 FFmpeg，脚本在本 skill 的 scripts/ 中。在剪辑大师内用 python studio.py cg 调用同一组脚本。用户只需描述效果，Agent 负责检查镜头、选择锚点、配置效果和核对结果。

在其他项目中使用时，若本 skill 目录存在 runtime.local.json，先读取其中本机的 Python、FFmpeg、Blender 和工作台位置，再通过实际绝对路径调用 scripts/cg.py。该本机配置由安装时生成，保持可移植的 skill 源码独立。

新机器或独立安装按 [运行环境](references/runtime-setup.md) 配置；基础剪辑依赖与可选模型分开安装，仓库不附带权重和本机路径。

复用的是场景理解、解算、合成与验收流程。每次由 Agent 查看实际帧、选择工具和生成本片效果；用户无需提供坐标、遮罩、JSON 或 Blender 代码。不同镜头可以使用不同后端。工具接入、推理成功、单片视觉达标分别记录，不承诺未经实测的跨场景效果。

适用于不同项目、不同素材和不同效果。先把用户的话拆成场景约束，例如哪个物体变化、运动轨迹、触发时刻、遮挡关系、光线和结尾。建立本次独立的计划与场景代码。用户指定的楼宇、桌面、人物周边或产品都是本片素材，不把其中一种写进通用工具的默认前提。

## 先观察与选镜头

沿用当前对话的素材范围。查看代表帧，并检查镜头是否有切换、运动模糊、前景遮挡和可追踪纹理。先用 5–10 秒连续镜头制作。参考视频只是视觉目标，作者宣传中的精度和覆盖范围需要实际验证。

用 `cg inspect SOURCE --out 新目录 --start 秒 --duration 秒` 提取接触表和带来源时间的帧，再实际查看图片。建立场景与相机后才做特效。

可见平面上的物体适合本工具的平面跟踪和近似镜头匹配，例如花盆前板、桌面、楼体立面、屏幕。Agent 在实际查看的参考帧上指定平面四角及宽高比。脚本复用 SIFT、MAGSAC 和 solvePnP，逐帧估计对应点与镜头位姿，并输出跟踪误差。已有相机标定数据时采用实际焦距；估算焦距时在交付中说明。

自由空间的大幅绕拍、多深度遮挡和严重畸变需要完整的三维解算与模型。遇到这些镜头，使用已配置的 Blender 原生跟踪或现有重建工具并另存其结果，或选择素材里适合验证的镜头。平面代理与程序模型只描述它们实际表示的几何。

固定机位使用 fixed，相机解算已有成果使用 imported，选面估计使用 planar。导入解算必须与底片尺寸、帧率和帧范围一致。近景人物、手部等需要挡住CG时，可在计划中传入白色前景遮罩。

`reconstructed` 调用本机 Depth Anything 3，从视频关键帧估计深度与相机，再用真实特征的三维/二维对应逐帧核对位姿。图片输入按单视图先验记录。当前可见网格取自参考视图；大幅绕到新的表面时需要补充其他视图、实际模型或外部解算。重投影或特征覆盖不够时会报错，Agent 要检查失败区间并换路由。

`segmentation.objects` 由 Agent 根据画面配置，SAM 2.1 传播整段视频的对象蒙版；target 提取真实表面，foreground 保护前景。`clean_plate` 可采用实际内部照片，或用本地 LaMa 修补被移走部分，再沿原片运动传播该参考。核对边缘和补景内容，生成的隐藏画面按创意补全记录。

## 颜色、效果与短样

实拍底片在图形合成前完成技术归一。用户说过 Log 时按项目色彩工作流确认曲线及设备。color.status 只有归一完成并记录依据后才填写 normalized_sdr。

读取 [计划与运行约定](references/plan-and-run.md) 和 [场景驱动的虚实合成](references/scene-aware.md)。先在本片 scene_analysis 中记录亲眼查看的物体轮廓、接缝、材质、光向、景深与前景，再设计哪个真实部分发生什么变化。空间坐标、分片方式和运动动机从这些观察推导；换一段素材，重新观察。用户无需填写这些参数。

优先利用项目已有 CAD 或实物模型匹配实际结构；可见表面可以用 source_surface 从实拍轮廓、纹理和可选的本地相对深度建立网格。拆开真实物体必须处理腾出来的空位：用有依据的内部参考、背景修补或三维结构补全，核对是否还有未移走的原物体、重复纹理或穿帮边缘。仅在屏幕前放一团物体无法交代这种变化。

为本片生成 scene_script 并实现 build_scene(context)。阅读 [自定义场景接口](references/custom-scenes.md)，使用原生 bpy、程序化几何、用户提供的 GLB/OBJ/FBX 或已核实的开放素材构建它。场景可以包含多个对象、轨迹和事件，共用跟踪、镜头、光照与合成流程。调用外部代码前查看其实际内容和依赖。

`visible_mesh` 提取对象轮廓、源图纹理和深度；硬质平面可对点云拟合，曲面使用 depth。`environment_mesh` 建立环境遮挡、阴影和碰撞代理；Cycles 用于实际光线追踪。`fracture` 根据对象蒙版与几何切分表面。树木生长、手腕配饰需要各自的几何和跟踪逻辑，不能由一次碎片演示推断已经实现。包约定见 [场景工程](references/scene-package.md)。

voxel-bloom、voxel-scatter、portal 和 scripts/scenes/orbit.py 保留为可运行的技术样例。只有它们的造型与本次视觉目标相符时才直接采用。

根据真实场景选择 effect.placement 中的位置、尺寸、深度与旋转。需要更复杂的破碎、粒子、体积或流体时，在本片脚本中使用可用的 Blender 原生功能并验证实际渲染。需要不可见表面或精细模型时，采用真实模型、重建成果或清楚标记的代理几何。

先生成效果最明显时刻的静帧，核对原物体到 CG 的接缝、厚度、腾空区域、遮挡、受光与投影，再渲染动画。贴图保留了原片光照，不代表转动后已有物理重照明；需要明显翻面时补充侧面材质、受光与阴影。连续查看起效和回收，避免贴纸式漂浮、硬跳变与不合理的复位。按本片需要修改场景并选择新的输出版本，持续保留用户原片。

`render --still` 同时输出底片合成预览 `CG-preview-帧号.png`，与最终视频共用补景、蒙版、线性光合成和透明度曲线。不要只检查透明 CG 层。

## 合成与交付

给出带 BGM 的 CG-effect.mp4、前后对照 CG-before-after.mp4、原生 tracked-effect.blend、镜头记录 camera.json 和实际 verification.json。用户请求保留原声时，在混音中保留相应声音并让音乐避开讲话，按本片制作工程处理。

逐段查看跟踪锚点和动态合成，尤其是边界、前景掠过和收尾。机器检查包含点对应误差、模型重投影、输出帧数和完整解码。最终音乐及音效需要试听，无法听辨时保留待人工试听状态。

先链接实际短样，再简述使用方法和本次经过验证的范围。源视频的不可见面、真实物理尺寸、产品功能或重建精度不能由视觉效果推定。用户对局部效果提出修改时，继续同一镜头的新版本。
